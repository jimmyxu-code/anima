## 第〇部分 · 北极星验收准则（一切决策的过滤器，用户 2026-08-21 亲定，不变）

**小凯存在的唯一理由（按优先级）：**

1. **极致体感**——面向用户的每一毫秒延迟、每一次打断、每一句话术都要像真人同事。
2. **交流顺畅**——对话是第一界面；一切操作都可以用对话完成。
3. **开箱即用**——C 端用户零配置上手，不许要说明书。
4. **支持定制**——能力、人格、技能都可插拔定制（插件化是为这个服务的，不是目的本身）。
5. **无所不能的执行**——凡是键盘鼠标能完成的操作，小凯都要能完成。
6. **不依赖超强模型的自进化**——它会自己学、自己写插件、沉淀技能，而不是靠换一个更贵的模型。

**决策纪律（对人和 AI 同效）**：任何架构/功能决策先过上面的过滤器，不能明确服务其中一条的不做；发现决策偏离目标——无论谁提的——停下来想清楚再动手；为改而改=浪费。**工程铁律与环境坑见根目录 `AGENTS.md`，此处不重复。**

**工程哲学补充（2026-08-31 用户终裁，未来保持执行）：**

1. **硬编码尽可能的少**：逻辑判断、尤其是意图识别（意思的识别），全部交给模型智能。机械正则只允许做"召回/保险丝"（安全 fail-closed 面：删/付/不可逆），绝不允许它来做"理解"。
2. **兜底件只是临时脚手架，不是系统本身**：凡因模型能力暂时不足而加的机械兜底（意图正则表/语气词表/话术表/硬规则分支），一律登记为【临时脚手架·挂账待拆】——写明它不是终态、写明拆除条件（模型裸判连续达标即拆），不许冒充系统本身长在主路上。模型能力一到，脚手架全拆。
3. **一切插件化、模块化、可热插拔**：新能力=插件（kernel 装配）；兜底件也必须是可插拔开关（拔掉不伤主路，模型单跑也是完整系统）。不许把临时机械件焊死在装配壳里。

## 第一部分 · 北极星与四层架构

**北极星：用户说一句话，这台电脑上没有任何事办不到。** 自动化走人类层级——看真实屏幕、动真实键鼠；C 端体感绝对一体（一个人格、一份记忆、一张嘴）。

**路线选择（已裁决）**："不换内核，换谁面对用户"——Windows 退居后台当执行层，智能体成为用户面对的壳。

**四层（每层停下都是完整产品；L2-L4 详见 `docs/02-愿景/`）**：

| 层 | 形态 | 状态（2026-08-23） |
|---|---|---|
| L1 助手级 | 住在 Windows 里的语音电脑伙伴"小凯" | **已上线迭代中**（本文第二部分） |
| L2 混合级 | Windows 生态 × 智能体的混合 OS 层 | 验证机已打通；商业化定位待重裁（见 03-商业） |
| L3 原生级 | 烧录器形态的 AI 原生用户层 | 构想（文档热备，不动代码） |
| L4 数字生命级 | 持久身份、自主目标、持续成长 | 构想；MEMORY.md/skills 是其胚胎 |

## 第二部分 · 现状：L1 建成了什么（08-23 冻结口径）

**现役架构（一段话）**：豆包全双工 S2S 端到端语音（语音人格/打断/判停归服务端）→ 语音层 FC 五工具（web_search / look_screen / run_task / task_status / recall_memory，真手真账）‖ ASR 终稿平行送 DeepSeek 路由脑（只判不答）→ 任务会话 → **exec-native 自有执行循环**（智能配档 flash/pro、只读 delegate 并发、本地两极安全闸）→ 前台 GUI（gui_agent 真人级键鼠+动作闸+接管检测）。播报走本地人格渲染 + say_hello 确定性通道（双工注入不触发作答是协议实锤）；文字框 task_overlay 沉默即上屏。

**关键数字（详见 `docs/05-台账/`）**：
- GUI 前台 30 条正式验收 **90.0%**（轨迹 60%→73.3%→83.3%→90%，P50 18.9s，0 人工接管）；grounding 云端 88%/5.8px。
- 离线测试 21 个 Python 文件全绿（现位于 `tests/`；TS/MJS 两个 node 测试在根，依赖 `extensions/`）。
- 语音实测：首 token 0.4-0.9s，纯对话 0.7-1.6s；**已知残留：对话偶发"说一半停"（三连修后待复测，嫌疑=喇叭回声进麦，AEC 未做）**。
- 体量：生产代码约 10k 行 Python；companion_rt.py（约 2.4k 行装配壳）是下一个拆分对象。

**08-22 三裁决（记档防回潮）**：① dsh 从运行时彻底退役（3081/9222 全停，执行只走 exec-native；`config exec_backend=dsh` 可恢复旧链路）；② 双工协议结论 probe 实锤（注入不触发作答/FC 回传只认 role=tool 形态/上行断流杀会话）；③ **任何协议/框架假设先写探针实测再信**——本项目三次大坑全是"凭文档猜"挖出来的（已入 AGENTS.md）。

## 第三部分 · 证据：深研结论（六路工程 + 三路商业）

**工程六路（2026-08-21，全文见 `docs/05-台账/2026-08-21-深研报告合集.md`）**：
1. DSH 的正确用法是挂插件进树不是当工具调——**已超越**：08-22 直接退役，教训沉淀为"外部框架先 probe 后集成"。
2. false success 被学界量化（45-48% 失败被谎报成功）→ 双证据判定/证据分级播报方向正确。
3. 语音痛点对口升级件 = 全双工端点（判停 -250ms/打断 -300ms/原生 FC）——**已落地主路**。
4. GUI 混合路线（UIA/DOM+视觉）是 2026 共识；差距在每步延迟与重复犯错恢复，解法是工程（投机批预测/grounding 缓存，缓办中）。
5. 路由与任务生命周期：三车道 + 级联升级 + 副作用登记册（已上线）。
6. 一体感来源 = 同一 identity/memory/expression/task-session——恰好四个插件（已上线）。

**商业三路（2026-08-23，独立完成于阅读用户构想之前，见 `docs/03-商业/`）**：
1. 竞品：一年五个同类产品死亡/收编；"常驻真实桌面+语音优先+真实键鼠+随时接管"全球无成型竞品；窗口 12-24 个月且正在关闭。
2. 单位经济（自家台账实测）：成本由"助手播报分钟数"驱动（0.45 元/min）；订阅额度单位应为播报分钟/天；BYOK 泄压。
3. 打法：国内大众 toC 是死局，切 prosumer；先收入后融资；合规路径=个体户→内测豁免→公开后 10 个工作日备案。
